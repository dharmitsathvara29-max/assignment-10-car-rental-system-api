A production-ready Car Rental & Vehicle Fleet Management RESTful API built with **Node.js**, **Express.js**, and **Supabase (PostgreSQL + Supabase Auth)**.

---

## 📌 Features

- **Relational PostgreSQL Schema**: Foreign key constraints (`ON DELETE RESTRICT`), data integrity checks (`valid_date_range`, category enum checks, rate constraints).
- **Date Collision Prevention**: Prevents double-booking via robust date range overlap logic (`existing.start_date <= new.end_date AND existing.end_date >= new.start_date`).
- **Dynamic Cost Calculation**: Automatically calculates rental cost (`(end_date - start_date in days) × daily_rate`), enforcing minimum 1-day rental.
- **Fleet State Management**: Automatic transitions between `available` ↔ `rented` ↔ `maintenance`.
- **Supabase JWT Authentication**: Secure routes utilizing Supabase Auth JWTs extracted from `Authorization: Bearer <token>` headers.
- **Relational Joins**: PostgREST joins between vehicles and rental history, and rentals with vehicle metadata.
- **Centralized Error Handling**: Uniform JSON error responses across all endpoints.

## 🗄️ Database Setup (Supabase)

1. Log in to [Supabase](https://supabase.com) and create a new project.
2. In the Supabase Dashboard, navigate to the **SQL Editor** tab.
3. Open [`db/schema.sql`](./db/schema.sql) and execute the SQL query to create tables, indexes, and constraints:

```sql
-- 1. Vehicles Table
CREATE TABLE vehicles (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  brand TEXT NOT NULL,
  model TEXT NOT NULL,
  year INT NOT NULL,
  category TEXT NOT NULL CHECK (category IN ('Sedan', 'SUV', 'Luxury', 'Hatchback', 'Electric')),
  daily_rate NUMERIC(10, 2) NOT NULL CHECK (daily_rate > 0),
  fuel_type TEXT NOT NULL,
  seating_capacity INT NOT NULL DEFAULT 5,
  status TEXT NOT NULL DEFAULT 'available' CHECK (status IN ('available', 'rented', 'maintenance')),
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- 2. Rentals / Bookings Table
CREATE TABLE rentals (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  user_id UUID NOT NULL, -- references Supabase auth.users
  vehicle_id BIGINT REFERENCES vehicles(id) ON DELETE RESTRICT,
  customer_name TEXT NOT NULL,
  customer_email TEXT NOT NULL,
  start_date DATE NOT NULL,
  end_date DATE NOT NULL,
  total_cost NUMERIC(10, 2) NOT NULL,
  status TEXT NOT NULL DEFAULT 'booked' CHECK (status IN ('booked', 'active', 'completed', 'cancelled')),
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  CONSTRAINT valid_date_range CHECK (end_date >= start_date)
);

-- Indexes for optimal lookup and collision prevention
CREATE INDEX IF NOT EXISTS idx_rentals_vehicle_dates ON rentals(vehicle_id, start_date, end_date, status);
CREATE INDEX IF NOT EXISTS idx_rentals_user_id ON rentals(user_id);
CREATE INDEX IF NOT EXISTS idx_vehicles_category_status ON vehicles(category, status);
```

4. Retrieve your **Project URL** and **anon/public key** from **Project Settings > API**.

## 🧪 Testing Flow: Booking Collision & Billing

The core requirement prevents overlapping reservations on the same vehicle for dates where the existing rental status is `booked` or `active`.

### Standard Overlap Condition
Two date ranges `[A_start, A_end]` and `[B_start, B_end]` overlap if and only if:
$$\text{existing.start\_date} \le \text{new.end\_date} \quad \text{AND} \quad \text{existing.end\_date} \ge \text{new.start\_date}$$

### Step-by-Step Test Walkthrough

#### Step 1: Register and Log In
```bash
# Register
curl -X POST http://localhost:5000/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{"name": "Dharmit Sathvara", "email": "dharmit@example.com", "password": "Password123!"}'

# Login to get ACCESS_TOKEN
curl -X POST http://localhost:5000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email": "dharmit@example.com", "password": "Password123!"}'
```
*Export your token:*
```bash
export TOKEN="YOUR_ACCESS_TOKEN_HERE"
```

#### Step 2: Insert a Vehicle (Vehicle #1)
```bash
curl -X POST http://localhost:5000/api/vehicles \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{
    "brand": "Tesla",
    "model": "Model 3",
    "year": 2024,
    "category": "Electric",
    "daily_rate": 85.00,
    "fuel_type": "Electric",
    "seating_capacity": 5
  }'
```

#### Step 3: Book Vehicle #1 for 2026-05-01 to 2026-05-05 (Success ✅ 201 Created)
- Duration: 4 days (2026-05-05 - 2026-05-01)
- Cost: $4 \times \$85.00 = \$340.00$
```bash
curl -X POST http://localhost:5000/api/rentals \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{
    "vehicle_id": 1,
    "start_date": "2026-05-01",
    "end_date": "2026-05-05",
    "customer_name": "Dharmit Sathvara",
    "customer_email": "dharmit@example.com"
  }'
```
**Response (201 Created):**
```json
{
  "success": true,
  "message": "Rental booked successfully",
  "data": {
    "id": 1,
    "user_id": "8b7e2...",
    "vehicle_id": 1,
    "customer_name": "Dharmit Sathvara",
    "customer_email": "dharmit@example.com",
    "start_date": "2026-05-01",
    "end_date": "2026-05-05",
    "total_cost": 340.00,

    "rental_days": 4,
    "daily_rate": 85.00

```

#### Step 4: Re-book Vehicle #1 for 2026-05-03 to 2026-05-07 (Collision Rejection ❌ 400 Bad Request)
- Date range `2026-05-03` to `2026-05-07` overlaps with `2026-05-01` to `2026-05-05`.
```bash
curl -X POST http://localhost:5000/api/rentals \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{
    "vehicle_id": 1,
    "start_date": "2026-05-03",
    "end_date": "2026-05-07",
    "customer_name": "Second Customer",
    "customer_email": "second@example.com"
  }'
```
**Response (400 Bad Request):**
```json

  "success": false,
  "message": "Vehicle already reserved during this timeframe"
```

## ☁️ Deployment Guide (Render)

1. Push your code to your GitHub repository:
   ```bash
   git add .
   git commit -m "feat: complete Car Rental API with Supabase auth and collision check"
   git push -u origin main
   ```

2. Sign in to [Render](https://render.com) using your GitHub account.
3. Click **New +** > **Web Service**.
4. Select your repository `assignment-10-car-rental-system-api`.
5. Configure the service:
   - **Name**: `car-rental-api`
   - **Runtime**: `Node`
   - **Build Command**: `npm install`
   - **Start Command**: `npm start`
   - **Instance Type**: `Free`
6. Add Environment Variables in the **Environment** tab:
   - `SUPABASE_URL`: Your Supabase Project URL
   - `SUPABASE_ANON_KEY`: Your Supabase Public Anon Key
   - `PORT`: `5000` (Render binds dynamically, fallback to 5000)
7. Click **Create Web Service**.
8. Once deployment completes, test the live URL:
   ```bash
   curl https://<your-service-name>.onrender.com/api/vehicles
   ```
